Agentic AI for billing adjustments on IBM watsonx

A working proof of concept on synthetic data for a common telecom problem: credit requests for customers who were billed wrong often arrive incomplete, and reviewers check each one by hand. I built two AI agents on IBM watsonx Orchestrate. One helps sales submit a complete request, the other recommends an outcome, and a person makes the final call.

What it does

  • Intake agent, for sales: asks for what is missing, pulls the customer's contracts, invoices and outage records, checks for duplicates, and submits a complete request with the evidence attached.
  • Review agent, for reviewers: recalculates the credit from live records, quotes the exact policy section, and recommends approve, partly approve, reject, or return for more information.
  • People decide: the reviewer makes the call. Credits over $20K also need a director, and over $100K a director and a VP. Every decision is saved with the AI's recommendation and the reason for any override.

How it is built

  • Agents: two agents in IBM watsonx Orchestrate, running on gpt-oss-120b, with 11 and 8 tools.
  • Tools: 18 Python tools the agents call for lookups, policy checks, approval levels and saving decisions.
  • Data: 9 tables of synthetic data in watsonx.data, queried through Presto over Iceberg tables with parameterized SQL.
  • Policies: 7 policy documents in a knowledge base the agents search with retrieval-augmented generation (RAG).
  • Build and deploy: planned and built with IBM Bob, IBM's AI coding assistant, and deployed to watsonx Orchestrate with Python scripts.

Keeping the numbers right

In early tests, the model made up policy quotes, a calculation and an approval level. So the agents no longer do any math: Python code calculates each credit with exact decimal arithmetic, quotes the policy word for word, and sets the approval level. The model explains the result.

def calc_approval_level(amount: Decimal) -> str:
    """Return approval level string per POL-001 §1 thresholds."""
    if amount > Decimal("100000.00"):
        return "Director and VP"
    elif amount > Decimal("20000.00"):
        return "Director"
    return "Reviewer"

API keys stay in an Orchestrate connection, never in the code or in front of the model, and each agent only gets the tools its role needs.

How I tested it

  • 19 unit tests check the math, and that every policy quote matches the policy text word for word.
  • 12 of 12 pending requests matched an answer key in scripted runs. The answer key was kept away from the AI.
  • Dry runs in Orchestrate's chat, end to end, as a reviewer and as a director.
  • Model choice: IBM Granite stopped calling tools once an agent had 11 of them. I tested the likely causes one at a time, then switched to gpt-oss-120b.

Built on synthetic data for a fictional telecom company. No employer data, documents or systems were used.
