Order-to-billing visibility with process mining

A BI team had tried for about two years to connect order records across systems, so no one could see where unbilled orders were stuck. I found the way to stitch them together.

The problem

Orders move through four core systems on their way from a closed-won deal to an invoice. Each system had its own keys, so there was no single view of an order's journey, and a share of orders silently never reached billing.

What I did

  • Mapped data fields across the four core systems, upstream and downstream, by reading their data models with SQL.
  • Found a key identifier in the order-entry system and combined it with others to stitch records end to end and build an event log for process mining.
  • Built a nightly ETL pipeline (SQL, Python, YAML) from Oracle into BigQuery for two of the systems, deployed through the team's existing GitHub workflow with automated CI checks.
  • Raised a data request that led another system team to build a new identifier, which the BI team now uses.

Result

A proof of concept that traced a few hundred orders end to end and showed, for the first time, where about 20% of closed-won orders in one product line stalled before billing.
